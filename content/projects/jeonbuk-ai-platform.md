**역할:** 팀장 · 한글/엑셀 웹 동시편집 모듈 담당  
**기간:** 2026.03 ~ 2026.06  
**협력:** 전북특별자치도청 · 전북소방본부  
**팀:** 4인

전북특별자치도청과 협력해 공무원들이 사용 중인 온프레미스 생성형 AI 플랫폼을 고도화하는 산학 프로젝트를 수행했습니다.

기존 플랫폼은 **약 5,000명의 공무원**이 사용 중이었으며, 프로젝트에서는 기존 시스템 위에 다음 4개 신규 기능을 구축했습니다.

- 119 다국어 통역 및 자동 기록 시스템
- 대도민 음성 챗봇
- 양식 기반 HWP 보고서 자동 생성
- 한글/엑셀 웹 동시편집

위 4개 기능은 **4인 팀 전체의 구축 범위**입니다. 저는 팀장으로 프로젝트 전반의 요구사항 조율에 참여하고, **한글/엑셀 웹 동시편집 모듈**을 직접 담당했습니다.

## 도청과의 협업

프로젝트는 일반적인 교내 캡스톤이 아니라 **전북특별자치도청**이 참여기관으로 함께한 산학과제였습니다.

도청 주무관님과 지속적으로 요구사항을 협의했고, 1차 시연 이후에는 **전북소방본부**를 직접 방문해 **실제 사용자의 피드백**을 받았습니다.

단순히 “구현 가능한 기능”보다 “실제 공무원이 업무에서 사용할 수 있는가”를 기준으로 기능과 품질을 조정했습니다.

## 한글·엑셀 웹 동시편집

도청은 공무원 주간 업무일지 등 문서를 여러 사용자가 웹에서 함께 편집할 수 있는 환경을 요구했습니다.

공공문서 특성상 단순 동시편집뿐 아니라 브라우저 화면에서도 문서가 깨지지 않고 정확하게 렌더링돼야 했습니다.

### 오픈소스 활용

엑셀은 **OnlyOffice** 오픈소스 동시편집 엔진을 **Nextcloud**와 연동했습니다.

한글(HWP)은 상용화된 웹 동시편집 솔루션이 없었기 때문에 **rHWP** renderer와 **Yjs**를 기반으로 한글 협업 계층을 직접 설계·구현했습니다.


## 한글 협업 계층 설계

HWP 파일을 클릭하면 rHWP editor를 `iframe`으로 로드하고 편집 room을 생성하도록 구성했습니다.

사용자 편집 동작을 **command object**로 직렬화하고 Yjs 공유 공간에 전달합니다.

Yjs는 다음 역할을 담당합니다.

- 실시간 동기화
- 충돌 처리
- 동일 room 사용자에게 변경 내용 broadcast


## rHWP 오픈소스

기능적으로 문서를 함께 편집할 수 있어도 실제 도청 공문서가 브라우저에서 깨지면 사용할 수 없었습니다.

도청 공직기강 문서를 기준으로 rHWP 렌더링 결과와 **한글 2024** 결과를 Claude Code를 활용하여 **픽셀 단위**로 비교했습니다.

대표 개선 항목:

- 사각 숫자·원문자
- 목차 점선·탭 정렬
- 가운뎃점 위치
- 그림 회전·앵커
- 글자 겹침
- 표 셀 병합 경계

각 오류의 root cause를 찾아 renderer code를 수정했습니다.

## rHWP 오픈소스에 contribute

수정 코드를 rHWP 공식 repository에 기여했고, **rHWP 본가에 10건의 수정사항을 반영**했습니다.

## 회귀 문제

특정 문서의 렌더링 오류를 수정한 뒤 다른 공개 샘플 문서에서 이전에 정상 동작하던 렌더링이 깨지는 회귀 문제가 발생했습니다.

사람이 매번 눈으로 모든 문서를 비교하는 방식으로는 재발을 막기 어렵다고 판단했습니다.

따라서 정상 렌더링 결과를 기준 이미지(snapshot)로 저장하고, 새 렌더링 결과와 픽셀 단위로 비교하는 **Visual Regression Guard Test**를 추가했습니다.

렌더링 결과가 달라지면 CI test가 실패하도록 구성해 이후 다른 code change로 동일 오류가 재발하는 것을 빠르게 탐지하도록 했습니다.

## 협업

프로젝트 과정에서 세 주체와 협업했습니다.

1. 전북도청
   - 업무 요구사항
   - 운영 시스템 제약
   - 공공문서 품질 기준

<br>

2. 전북소방본부
   - 실제 현장 사용자 피드백
   - 서비스 적용 관점
   
<br>

3. rHWP 오픈소스 메인테이너
   - code quality
   - regression
   - upstream contribution 기준
   - 카톡으로도 직접 소통하며 협업

각 이해관계자의 요구를 기술적으로 해석하고 구현 결과를 다시 피드백받는 과정을 반복했습니다.

## 결과 및 수상

- SW 캡스톤디자인 경진대회 최우수상
- 전북특별자치도지사 표창
- rHWP 본가 10건 수정사항 반영
- 도청·소방본부 현장 피드백 반영

## 배운 점

실제 AX 프로젝트에서는 기술 구현만큼 기존 시스템과 사용자의 업무를 이해하는 것이 중요하다는 점을 배웠습니다.

도청의 요구사항을 분석하고, 오픈소스를 적극 활용하며, 상용 솔루션이 없던 한글 협업 영역에 개발을 집중했습니다.

이후 실제 공문서를 기준으로 품질을 검증하고 오픈소스 upstream까지 수정사항을 반영하면서 운영 수준의 안정성을 확보하는 과정을 경험했습니다.

**고객 요구사항 → 기술 대안 비교 → 모듈 설계·구현 → 현장 피드백 → 품질 검증 → 운영 수준 고도화**로 이어지는 AX 프로젝트 수행 경험을 쌓았습니다.
