소상공인은 카드·상권·고객 데이터에 접근할 수 있어도 이를 실제 마케팅 행동으로 바꾸기는 어렵습니다. 기존 서비스가 분석 결과를 보여주는 데 그친다면, Sentinel은 데이터를 점주가 바로 적용할 수 있는 **실행 가능한 전략**으로 전환하는 것이 목표였습니다.

## 로컬 이벤트가 정말 매출에 영향을 주는가?

Agent에게 전략을 생성시키기 전에 로컬 이벤트가 실제 상권 매출에 영향을 주는지부터 검증했습니다.

**성수를 처치군, 뚝섬을 통제군**으로 두고 이벤트 전후의 매출 변화를 비교하는 **DiD(Difference-in-Differences)** 분석을 적용했습니다. 단순 전후 비교가 아니라 통제군의 공통 변화까지 고려해 이벤트와 연관된 효과를 분리하도록 설계했습니다.

### 평행추세와 강건성 검증

이벤트 이전 두 지역의 움직임이 유사한지 확인해 **평행추세** 가정을 검토했습니다.

이후 재방문 고객 비중, 신규 고객 비중, 여성 20대 이하 고객 비중 등을 추가한 **강건성 검증**을 수행했습니다.

통제변수를 추가한 후에도 동일 업종 매출금액 비율에 대한 DiD 계수는 약 +2.75%였으며 통계적으로 유의한 결과가 유지됐습니다. 모든 이벤트에 일반화한 수치가 아니라 **해당 분석 설정에서 통제 후에도 약 +2.75%의 유의한 효과가 관찰된 결과**입니다.

## 하나의 분석을 로컬 이벤트 DB로 확장

성수 팝업 한 사례에서 끝내지 않고 성동구의 이벤트 시점과 지역 조합에 대해 동일한 DiD 분석을 반복했습니다.

분석 결과 중 유의한 이벤트·지역 조합을 구조화해 **로컬 이벤트 DB**로 확장했습니다.

성수의 팝업뿐 아니라 마장동의 명절 축산 수요, 한양대의 대학축제·시험기간, 서울숲의 벚꽃 시즌처럼 각 지역의 로컬 이벤트를 마케팅 기회로 활용할 수 있도록 설계했습니다.

## EDA

단순한 분석 차트가 아니라 점주가 실제로 궁금해할 질문을 기준으로 EDA 했습니다.

### 어디서 어떤 경쟁을 하고 있는가?

업종·상권별 경쟁 강도를 분석하고 각 상권을 이벤트 중심, 생활·커뮤니티 중심 등으로 해석했습니다.

### 누구에게 팔아야 하는가?

이벤트 DB의 타겟 고객과 가맹점의 업종별 고객 특성을 비교해 이벤트-가맹점 적합성을 분석했습니다.

### 가게의 성장 동력은 무엇인가?

재방문율과 신규 고객 유입을 분석해 신규 유입형, 단골 안정형, 정체·위기형 등 가게 상태를 진단하도록 구성했습니다.

### 숨겨진 기회와 위협은 무엇인가?

시즌, 배달, 지역 소비 변화 등 점주가 놓치기 쉬운 변수를 함께 분석해 선제적인 마케팅 전략으로 연결했습니다.

## RAG + 5개 전문 Agent

Sentinel은 하나의 범용 챗봇이 아니라 사용자의 질문 의도를 먼저 분류한 뒤 문제에 맞는 **5개 전문 Agent**와 데이터 소스를 선택하도록 구성했습니다.

### 1단계 — 질문 라우팅

채널, 재방문, 진단, 트렌드, 충성도 등의 키워드와 질문 의도를 분석해 task type을 분류하는 **질문 라우팅**을 구성했습니다.

### 2단계 — 전문 Agent 선택

질문 목적에 따라 다음 5개 전문 Agent 중 적합한 역할을 선택합니다.

- 마케팅 채널 전문가
- 고객 유지 전문가
- 문제 진단 전문가
- 트렌드 분석 전문가
- 고객 충성도 전문가

### 3단계 — RAG 근거 수집

Agent별 **RAG** 정책에 따라 필요한 데이터를 선택해 검색합니다.

주요 데이터:

- 신한카드 분석 데이터
- 업종/지역 CSV
- 이벤트 DB
- DiD 분석 결과

### 4단계 — Gemini 기반 전략 생성

검색된 근거와 Agent의 전문가 역할을 **Gemini** 기반 LLM에 입력해 점주별 마케팅 전략을 생성합니다.

### 5단계 — 출처가 있는 실행안

최종 답변에는 사용한 데이터의 출처를 명시해 사용자가 왜 해당 전략을 추천받았는지 확인할 수 있는 **출처가 있는 실행안**으로 설계했습니다.

## 5개 Agent를 분리한 이유

모든 질문을 하나의 `prompt`로 처리하면 관련 없는 데이터를 함께 검색하거나 지나치게 일반적인 답변을 생성할 수 있다고 판단했습니다.

질문 목적에 따라 Agent를 분리하고 각 Agent마다 사용할 데이터와 역할을 다르게 정의해 **질문 유형 → 데이터 선택 → 근거 수집 → 전략 생성** 과정이 일관되게 동작하도록 설계했습니다.

## 분석을 비즈니스 실행 과제로 연결

Sentinel의 목적은 “매출이 올랐다”는 분석 결과를 보여주는 것이 아니라 점주가 다음에 무엇을 해야 하는지 결정하도록 돕는 것이었습니다.

시즌 트렌드라면 프로모션 테마를, 재방문율이 문제라면 멤버십·리워드 전략을, 신규 고객 유입이 문제라면 타겟 채널과 콘텐츠 전략을 제안하도록 구성했습니다.

## 수상

제13회 빅콘테스트 장려상

## 배운 점

AI Agent의 답변 품질은 LLM 자체뿐 아니라 어떤 데이터를 근거로 선택하고 어떤 분석을 선행했는가에 크게 좌우된다는 점을 배웠습니다.

데이터 분석 → 가설 검증 → 유의 결과 구조화 → 질문 라우팅 → RAG → 실행 전략 생성까지 하나의 프로세스로 연결하면서 데이터를 단순한 인사이트가 아니라 사용자의 의사결정을 돕는 비즈니스 실행 과제로 전환하는 경험을 했습니다.
