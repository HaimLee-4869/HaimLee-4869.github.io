항만 운영을 단순한 물류 자동화 문제가 아니라 운영과 행정 전반의 AX 문제로 바라봤습니다. **항만공사 현업 인터뷰**를 통해 여러 시스템에 분산된 데이터, 반복적인 서류 검수, 잦은 규정 확인, 예측하기 어려운 장치장 혼잡이 서로 연결된 문제라는 점을 확인했습니다.

특히 현장에서는 새로운 시스템으로 전면 교체하는 것보다 **기존 TOS**를 활용하면서 필요한 AI 기능을 확장하는 방향과, 자동화 결과에 대한 신뢰성과 판단 근거가 중요하다는 요구가 있었습니다.

## 현장 인터뷰에서 AX 구조를 설계하다

### 기존 TOS를 교체하지 않은 이유

기존 TOS에는 이미 많은 비용과 운영 프로세스가 축적되어 있기 때문에 전면 교체는 비용·기간·안정성 측면에서 현실성이 낮다고 판단했습니다.

이에 Port-AX를 기존 TOS 위에 API로 연결되는 **지능형 확장 시스템**으로 설계했습니다. 기존 운영 시스템은 유지하면서 규정 대응, 서류 검수, 혼잡도 예측, 물동량 예측 등 AI 기능을 모듈 형태로 추가하는 **API 연동형 아키텍처**입니다.

실제 수행 범위는 API 연동형 아키텍처 설계, TOS 연동 상태를 표현한 MVP UI, 향후 TOS 연동 로드맵 수립이며 실제 운영 TOS와의 연동을 완료한 단계는 아닙니다.

## 운영 효율화와 행정 자동화를 위한 4개 AI 모듈

Port-AX는 현업 인터뷰에서 확인한 문제를 ‘행정 자동화’와 ‘운영 효율화’ 두 축으로 나누고 4개 AI 모듈로 설계했습니다.

### Agent 1 — RAG 기반 항만 규정 대응

잦은 법규 개정과 여러 내부 매뉴얼에서 필요한 정보를 찾는 행정 업무를 줄이기 위해 **RAG** 기반 규정 검색·답변 기능을 설계했습니다.

사용자가 자연어로 질문하면 관련 법규와 매뉴얼을 검색하고, 답변과 함께 근거가 되는 출처·조항을 제시하도록 구성했습니다.

핵심은 단순 LLM 답변이 아니라 **판단 근거와 출처**를 보여주는 자동화였습니다.

### Agent 2 — AI-OCR 기반 서류 검수

B/L, Invoice 등 비정형 서류를 **AI-OCR**로 텍스트화하고 주요 필드를 교차 검증하는 서류 검수 기능을 구현했습니다.

오류가 발견되면 단순히 정상/오류만 표시하는 것이 아니라 오류 필드와 사유를 `JSON` 구조로 리포트하도록 설계해 사람이 검토 결과를 확인할 수 있도록 했습니다.

서류 검토시간 단축은 실제 측정 결과가 아니라 향후 현장 적용 시 검증할 목표 KPI로 구분했습니다.

### Agent 3 — 장치장 혼잡도 예측

예측하기 어려운 선박 도착과 장치장 포화를 사후 대응이 아닌 선제 대응 문제로 정의했습니다.

10분 단위로 재구성한 실데이터를 기반으로 **CNN+LSTM** 혼잡도 예측 모델을 학습했고, **내부 테스트에서 R² 0.9991**을 기록했습니다.

예측 결과는 차트로만 보여주는 것이 아니라 향후 장치장 포화 가능성과 재배치 필요성을 운영자가 판단할 수 있도록 자연어 브리핑 형태로 연결했습니다.

### Agent 4 — 컨테이너 물동량 예측

향후 인력·장비 배분을 지원하기 위해 일별 컨테이너 입고량 예측 기능을 개발했습니다.

**LightGBM·CatBoost·MLP** 기반 앙상블 모델을 적용했고, 초기 테스트에서는 MAPE 24.56%를 기록했습니다.

이후 전일 물량, 3일/7일 이동평균 등 시계열 파생변수를 추가해 **내부 심화 테스트에서 MAPE 2.95%**까지 개선했습니다.

이 과정은 단순히 더 복잡한 모델을 사용하는 것보다 데이터의 시간적 구조를 반영하는 **Feature Engineering**이 성능 개선에 중요하다는 점을 보여줬습니다.

## 4개 AI 기능을 하나의 운영 화면으로

각 AI 기능을 개별 데모로 두지 않고 평균 대기시간, 처리량, 서류 오류, 혼잡도 등의 핵심 지표를 한 화면에서 확인할 수 있는 **통합 대시보드 MVP**를 구현했습니다.

이를 통해 Port-AX가 여러 AI 모델의 모음이 아니라 항만 운영자의 의사결정을 지원하는 통합 운영 플랫폼이라는 구조를 시각적으로 구현했습니다.

## 기술에서 실행 로드맵까지

기술 구현에서 끝내지 않고 실제 현장 적용을 가정한 **12개월 AX 로드맵**을 설계했습니다. 아래 단계는 완료 실적이 아닌 향후 실행계획입니다.

### 1단계 — 기획 및 환경 구축 (0~2개월)

- 항만공사 현업 TF 구성
- 데이터 접근 권한 확보
- TOS Staging 환경 협의
- 4개 AI 모듈 요구사항 정의

### 2단계 — PoC 및 핵심 모델 개발 (2~6개월)

- 확보된 운영 데이터 기반 예측 모델 재학습
- RAG·AI-OCR 파이프라인 구축
- AI API 및 MVP 고도화

### 3단계 — TOS 연동 및 통합 테스트 (6~8개월)

- TOS와 Port-AX 간 API 연동
- 실시간 데이터 파이프라인 검증
- 현업 사용자 대상 기능 테스트

### 4단계 — 현장 베타 및 안정화 (8~12개월)

- 1개 터미널 베타 적용
- 현업 사용자 피드백
- 모델 모니터링 및 파인튜닝
- 운영 가이드 및 정식 버전 완성

## 목표 KPI

다음 항목은 현재 달성 성과가 아니라 12개월 현장 적용 시 검증할 목표 KPI입니다.

- 규정·매뉴얼 검색 시간 단축
- 건당 서류 검토 리드타임
- 장치장 포화 발생
- D&D 비용
- 인력·장비 배치 오차
- 현업 사용자 만족도

## 배운 점

이 프로젝트를 통해 AX는 새로운 AI 모델을 도입하는 것보다 기존 업무와 시스템을 먼저 이해하는 것에서 시작한다는 점을 배웠습니다.

현업 인터뷰를 통해 문제를 정의하고, 기존 TOS를 유지해야 하는 비용·안정성 제약을 고려해 API 연동형 **To-Be** 구조를 선택했습니다. 이후 문제를 4개의 AI 모듈로 나누어 MVP로 검증하고, 다시 하나의 운영 대시보드와 12개월 실행 로드맵으로 연결했습니다.

이를 통해 현업 문제 정의 → **As-Is** 분석 → 기술 대안 설계 → MVP 검증 → **To-Be** 아키텍처 → 실행 로드맵으로 이어지는 AX 문제 해결 과정을 경험했습니다.
