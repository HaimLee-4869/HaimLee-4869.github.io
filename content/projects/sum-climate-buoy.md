기존 스마트 부표 사업에서 생성되는 데이터를 단순 수집에 그치지 않고, 해양 위험을 예측하는 AI 데이터 서비스로 확장하는 프로젝트를 진행했습니다.

제주 해역의 스마트 부표 데이터와 해양기상·사고 데이터를 결합해 해상 활동 위험도를 분석하고, 예측 결과를 지자체·어업·해양레저 현장에서 활용할 수 있는 대시보드와 알림 서비스로 연결했습니다.

## 113만 건 해양 데이터를 하나의 학습 데이터셋으로

스마트 부표의 유향·유속 데이터 **1,128,960건**, 마라도·서귀포·추자도 해양기상 관측 데이터, 해양사고 127건을 수집했습니다.

결측치·이상치 처리 이후 위치와 시간을 기준으로 데이터를 **시공간 조인**하고, 시계열 변화량과 통계값 등을 가공해 **26개 피처**의 ML 학습 데이터셋을 구축했습니다.

전처리 흐름:

원천 데이터 수집  
→ 결측치·이상치 처리  
→ 시공간 조인  
→ Feature Engineering  
→ 학습 데이터셋 생성

## XGBoost — 사고를 놓치지 않는 방향으로

해양사고 데이터가 정상 관측보다 적은 불균형 데이터임을 고려해 단순 Accuracy보다 위험 상황을 놓치지 않는 Recall을 중요 지표로 봤습니다.

모델 비교와 threshold 분석을 거쳐 **XGBoost**를 최종 모델로 선정하고 **threshold 0.4**로 설정했습니다.

최종 내부 평가:

- **Recall 82.74%**
- ROC-AUC 0.7646
- Precision 68.2%
- F1-Score 74.8%
- 입력 피처 26개

이 수치는 실제 현장의 사고 예방 성과나 서비스 정확도가 아니라 모델의 내부 평가 결과입니다.

## 모델을 AWS 예측 API로 서비스화

모델 파일만 만드는 데서 끝내지 않고 실제 서비스에서 사용할 수 있도록 AWS 환경에 추론 구조를 구성했습니다.

XGBoost 모델, scaler, threshold 설정을 Docker Image로 패키징해 ECR에 저장하고 **AWS Lambda**에서 추론하도록 배포했습니다.

이후 **API Gateway**의 REST API를 연결해 웹 대시보드에서 위험예측 요청을 전송하고 `LOW` / `MEDIUM` / `HIGH` 결과를 받을 수 있도록 구현했습니다. 웹 대시보드는 S3 정적 웹 호스팅으로 배포했습니다.

## Sentinel-2 위성 데이터 연동

AWS Open Data Program에서 제공하는 **Sentinel-2** 위성 데이터를 연동해 제주를 포함하는 6개 위성 타일을 대시보드에 오버레이했습니다.

스마트 부표가 제공하는 국지적인 실측 정보와 위성 기반의 광역 공간 정보를 한 화면에서 함께 탐색할 수 있도록 구성했습니다.

XGBoost 위험예측은 부표·기상·사고 기반의 26개 피처로 학습했고, Sentinel-2는 AWS Open Data 기반 위성 레이어의 연동·시각화에 사용했습니다. Sentinel-2 이미지를 XGBoost 학습 피처로 사용하지 않았습니다.

## 통합 해양 관제 대시보드

Leaflet 기반 지도에 다음 정보를 통합했습니다.

- **142개 스마트 부표 그리드**의 해류 벡터
- Sentinel-2 6개 위성 타일
- 마라도·서귀포·추자도 등 주요 위치
- 해양 위험예측 API 결과
- 사고 위치·시계열·관측소 비교 등 분석 자료

사용자가 해양 조건을 입력하면 예측 API를 호출해 `LOW` / `MEDIUM` / `HIGH` 위험도를 표시하도록 구현했습니다.

## HIGH 위험을 실제 알림으로 연결

위험예측 결과가 `HIGH`일 경우 대시보드 표시로 끝내지 않고 **AWS SNS**와 별도 Lambda를 연결했습니다.

위치, 위험도, 파고, 풍속, 수온 정보를 포함한 경고 이메일을 자동 발송하도록 구현해 **데이터 수집 → AI 예측 → 위험 판단 → 사용자 알림**으로 이어지는 서비스 흐름을 완성했습니다.

## 제조업에서 AI 데이터 서비스로

스마트 부표를 판매하는 것만으로 끝나는 것이 아니라 부표에서 지속적으로 생성되는 데이터를 새로운 서비스 자산으로 활용할 수 있다고 판단했습니다.

지자체에는 해양 위험도와 관제 데이터를 제공하는 **B2G** 데이터 서비스, 양식업·해양레저 사업자에는 위험 알림과 예측 정보를 제공하는 **B2B** 데이터/API 서비스로 확장하는 비즈니스 모델을 설계했습니다.

이는 서비스·비즈니스 모델 설계 단계이며 실제 계약이나 매출이 발생한 성과가 아닙니다.

## 배운 점

이 프로젝트를 통해 모델 성능만 높이는 것과 실제 서비스를 만드는 것은 다른 문제라는 점을 배웠습니다.

113만 건의 원천 데이터를 전처리하고 모델을 개발한 뒤 AWS API로 배포하고, 위성·지도·알림 시스템까지 연결하면서 **데이터 수집 → 분석 → ML → 배포 → 사용자 의사결정**으로 이어지는 **End-to-End AI 서비스** 구현을 경험했습니다.

또한 기존 제조 사업에서 생성되는 데이터를 B2G·B2B 데이터 서비스로 전환하면서 기술을 새로운 비즈니스 모델로 확장하는 **AX** 관점을 경험했습니다.
